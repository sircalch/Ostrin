The roadmap

Grow the language
in the right order.

Ostrin is not pretending to be finished. The roadmap keeps the dependency chain visible: semantics first, then runtime, tooling and applications.

public workdesign → code → testsno false promises

Build order

Every milestone earns the next one.

A language becomes trustworthy by closing the loop between a written rule, a compiler implementation and examples that prove the behavior.

complete / 01

Design the semantic core

The initial language decisions are recorded and consolidated in the design archive.

  • types and quantities
  • traits and generics
  • errors and patterns
  • modules and concurrency
complete / 02

Validate it with a working compiler

A Rust compiler and interpreter now exercise the core through automated tests and source examples.

  • lexer and parser
  • static checker
  • interpreter
  • 61 tests passing
next / 03

Make diagnostics useful

Good errors are part of the language. The next layer is source spans, structured diagnostics and messages that help people fix the program.

  • source-aware spans
  • better type errors
  • match exhaustiveness
next / 04

Build the real runtime surface

The prototype needs a standard library, I/O and a runtime that can interact with the operating system instead of only simulating behavior.

  • standard library
  • files and processes
  • real concurrency
future / 05

Package applications

Once the semantics and runtime are stable, Ostrin can target practical distribution: executable applications, native code and platform bindings.

  • .exe packaging
  • native backend
  • WebAssembly
future / 06

Open the ecosystem

Tooling, packages and community surfaces should follow real capability, not marketing promises.

  • public package registry
  • browser playground
  • stable VS Code LSP

Definition of done

Show the work.

Each feature should be discoverable in the docs, demonstrated by an example, protected by a test and visible in the editor or command line when it is ready.

  • Specification says what the feature means
  • Compiler implements the behavior
  • Passing and failing examples cover it
  • Documentation explains how to use it
  • Roadmap marks its actual state
