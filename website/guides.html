Install the compiler

Ostrin is an experimental developer release for Linux x86_64, macOS ARM64 and Windows x64. The installers download the release archive, verify its SHA-256 checksum and check ostrinc --version.

# Linux x86_64 or macOS ARM64
curl --fail --location https://raw.githubusercontent.com/sircalch/Ostrin/main/scripts/install.sh \
  --output /tmp/ostrinc-install.sh
sh /tmp/ostrinc-install.sh --version 0.1.0
# Windows PowerShell
$installer = Join-Path $env:TEMP 'ostrinc-install.ps1'
Invoke-WebRequest -UseBasicParsing https://raw.githubusercontent.com/sircalch/Ostrin/main/scripts/install.ps1 -OutFile $installer
powershell -ExecutionPolicy Bypass -File $installer -Version 0.1.0 -AddToPath
ostrinc --version
ostrinc --run examples/hello.ostrin

To build from source instead: cargo build --release --manifest-path compiler/Cargo.toml. Package-manager channels (Homebrew, winget, Scoop, Chocolatey, AUR) are not available yet.

Create a project with dependencies

--new creates a manifest and a main.ostrin with a test. Dependencies are local paths or Git repositories; builds write a deterministic ostrin.lock.

ostrinc --new my_project
ostrinc --run --project my_project
ostrinc --locked --run --project my_project   # require the existing lockfile
ostrinc --fetch --run --project my_project    # explicitly fetch Git dependencies
[package]
name = "my_project"
version = "0.1.0"
entry = "main.ostrin"

[dependencies]
plot = { path = "../plot" }

There is no public package registry yet. See the package design ↗.

Test and format

Functions named test_* are tests. assert_eq reports both values when it fails.

ostrinc --test examples/testing.ostrin
ostrinc --test --project my_project
ostrinc --fmt --check main.ostrin

Compile to native code

The native backend transpiles to C and compiles it with gcc, clang or cc (or OSTRIN_CC). The interpreter is the semantic reference, and a differential test compares every example against it.

ostrinc --compile examples/collections.ostrin
ostrinc --compile --leak-check examples/ownership_primitives.ostrin
ostrinc --compile --native-threads examples/native_threads.ostrin
ostrinc --emit-c examples/lab_pipeline.ostrin

Constructs outside the migrated HIR/IR families use a verified fallback; a few are rejected with a clear error instead of compiling with different semantics.

Build WebAssembly (WASI)

Programs compile to wasm32-wasip1 with the WASI SDK's clang; cancellation uses WebAssembly exception handling, so the host must support it. The compiler itself also runs as WASI — that is what powers the playground and the Lab.

export OSTRIN_WASI_CC=/path/to/wasi-sdk/bin/clang
ostrinc --compile --target wasm32-wasi examples/hello.ostrin
cargo build --manifest-path compiler/Cargo.toml --target wasm32-wasip1 --release

Use Visual Studio Code

The extension in vscode-ostrin/ uses ostrinc --lsp for diagnostics, hover, completion, definitions, references, rename and semantic tokens, and ostrinc --dap for breakpoints, stepping and variables. It is distributed as a local VSIX, not through the Marketplace.

cd vscode-ostrin
npx --yes @vscode/vsce package
code --install-extension ./ostrin-language-support-0.4.0.vsix

How this site proves its results

The Scientific Lab, the Cookbook and the compiler pipeline come from website/lab-data.js, generated by scripts/lab-data.mjs from programs in examples/ and run with ostrinc.wasm. CI regenerates it and fails when a source, a recorded output or a static page output drifts. Version, counts and release status come from scripts/site-facts.mjs.

node scripts/lab-data.mjs            # check recorded outputs
node scripts/website-metadata.mjs     # check version, counts and release facts
node scripts/website-check.mjs        # links, evidence, claims
