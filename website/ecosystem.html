The ecosystem

The language is the
beginning of the tool.

A useful language needs a compiler, an editor, a way to learn, a way to share code and a path to real applications. Ostrin is building those surfaces in public.

Where we are

The ecosystem starts with a solid core.

Today, Ostrin has a Rust compiler and interpreter, a growing set of semantic examples, design specifications and an initial VS Code extension.

Tools around Ostrin

Every surface has a job.

The goal is not to collect integrations. It is to make the path from an idea to a checked, understandable program feel coherent.

01

Compiler and interpreter

Check a file, inspect its AST or run it through the current Rust implementation.

02

Visual Studio Code

Open `.ostrin` files with the official logo, syntax support and compiler commands.

03

Design repository

Seventeen design documents record the language decisions and their trade-offs.

04

Examples as validation

Programs and failure cases act as an executable conversation with the design.

05

Native applications

Executable packaging and a native backend are planned after the semantic core matures.

06

WebAssembly

A browser playground is a future target once the runtime and toolchain can support it.

A deliberate ecosystem

No imaginary package count.

Ostrin is early. The site will never present a future registry as if it were already mature. Each capability will move from design, to implementation, to a documented example.

See the build order ↗
  • Design: describe the behavior and its constraints
  • Implementation: make the compiler or runtime support it
  • Validation: add passing and failing examples
  • Tooling: expose the feature in docs and the editor
  • Release: package it for people outside the repository
