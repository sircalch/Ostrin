Keep the claims separate.

This page publishes the machine-readable quality scorecard dimension by dimension. It does not compress tests, backend coverage, ownership, reproducibility and release readiness into one invented number.

Compiler backend

Native lowering has a visible boundary.

The ratchet counts functions generated through IR and HIR, with the remaining AST fallback kept explicit.

Ownership

Memory behavior is tracked by evidence.

The ownership matrix separates tested cells, promoted support and known limitations so a broad claim cannot hide an unverified boundary.

Numerical validation

Residuals stay attached to the run.

The analytic matrix suite checks interpreter/native parity, residual tolerances and native allocation cleanup. A local report is useful evidence; CI status is shown separately.

Scientific effects

Effect coverage stays conservative.

The inventory publishes resolved and unresolved operation edges separately. Counts are distinct function-operation pairs, not source callsite totals; an incomplete inventory is visible instead of being presented as a static purity guarantee.

Reproducibility

R-levels describe what can be replayed.

R0 records exact replay evidence in the CI configuration; R1 and R2 add seeded or input-snapshot contracts; R3 adds host-bound provenance and a closed conservative effect row at the entrypoint. The scorecard separates fixtures claiming the R3 replay level from bundles passing the structural CI capture gate. Module-wide symbolic callbacks remain visible as diagnostics; a closed row is not a purity proof.

GitHub Linguist

Recognition follows public use.

The local proposal, grammar and representative MIT samples are prepared. The external snapshot currently reports the public extension count and keeps the upstream PR pending until Linguist's usage threshold and distribution review are met.

Release readiness

v0.2 is a checklist, not a slogan.

Open criteria stay visible. A release candidate requires every mandatory dimension to become READY with its evidence attached.

How to read this

Use the source artifacts.

The scorecard is generated from repository files and records its source revision. Read the design documents and validation artifacts before making a claim about production readiness.
