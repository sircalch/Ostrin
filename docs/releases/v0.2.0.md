Ostrin 0.2.0 is an **experimental release candidate** of the Ostrin compiler
(`ostrinc`). It builds on the 0.1.0 line with stronger scientific ownership,
numerical validation, reproducibility and visualization workflows. It is meant
for evaluation and bug reports, not production use; the 0.x compatibility policy
allows syntax, diagnostics and APIs to change.

These notes define Ostrin `0.2.0` as an experimental 0.x release. The final
tag workflow builds fresh archives and SHA-256 checksums from the exact tag;
RC artifacts named `ostrinc-v0.2.0-rc.<source-sha>-<target>` are separate and
must not be reused as final release assets. See the publication procedure for
revision identity and release verification steps.

## Supported platforms

| Platform | Candidate archive |
| --- | --- |
| Linux x86_64 (glibc) | `ostrinc-v0.2.0-rc.<source-sha>-x86_64-unknown-linux-gnu.tar.gz` |
| macOS ARM64 (Apple silicon) | `ostrinc-v0.2.0-rc.<source-sha>-aarch64-apple-darwin.tar.gz` |
| Windows x64 | `ostrinc-v0.2.0-rc.<source-sha>-x86_64-pc-windows-msvc.zip` |
| WASI Preview 1 | `ostrinc-wasm32-wasip1.tar.gz` |

Each native archive has a matching `.sha256` sidecar and contains the compiler,
license, README and runnable examples. The WASI package contains the compiler,
its `SHA256SUMS`, README and the 28-program runtime matrix. CI tests the native
compiler and extracted archives on each platform, verifies checksums, and runs
both the hello example and packaged path-dependency project. CI also runs the
WASI compiler under Node and smoke-tests its runtime matrix.

## Install

After publication, install explicit version `0.2.0` using the repository
installer and verify the attached SHA-256 checksum before running the compiler.
During candidate preparation the public installer continues to resolve the latest
published version. RC archives are available only from their workflow run. See
[`v0.2.0-publication.md`](v0.2.0-publication.md) for the full procedure.

The native workflow artifact names are `x86_64-unknown-linux-gnu`,
`aarch64-apple-darwin` and `x86_64-pc-windows-msvc`. For example, after locating
the candidate run ID:

```sh
gh run download <candidate-run-id> --name x86_64-unknown-linux-gnu
tar -xzf ostrinc-v0.2.0-rc.<source-sha>-x86_64-unknown-linux-gnu.tar.gz
sha256sum --check ostrinc-v0.2.0-rc.<source-sha>-x86_64-unknown-linux-gnu.tar.gz.sha256
./ostrinc --version
./ostrinc --run examples/hello.ostrin
```

For Windows PowerShell, download the `x86_64-pc-windows-msvc` workflow artifact,
verify its `.sha256` sidecar with `Get-FileHash -Algorithm SHA256`, expand the ZIP
and run `ostrinc.exe --version` followed by `ostrinc.exe --run examples/hello.ostrin`.
The version command must print `ostrinc 0.2.0`. These candidate archives are not
referenced by the public install scripts.

## What is included

- Typed HIR/IR and native lowering for the measured core: 7,198 IR and 41 HIR
  bodies, with zero AST fallbacks. This measured inventory does not imply that
  every valid source shape has native HIR/IR support.
- Verified ownership for the tested `dyn Trait`, managed enum, records,
  collections and function-value combinations listed in
  [`docs/ownership-matrix.md`](../ownership-matrix.md).
- Scalar `Measurement<Float>` ownership through supported records, calls,
  cloning, lists, branches, loops, `Phi`, closures, results and deferred tasks.
- LU, Cholesky, QR, SVD and symmetric eigenpair numerical checks against
  independent residuals and declared tolerances.
- Scientific plots, tables, 3D scenes and animations, with a browser gallery,
  playground and reproducible figure bundles.
- R1 replay for registered input-driven experiments, plus source, input,
  dependency, effect and runtime evidence. Runtime provenance remains partial.
- Native and WASI execution, a community starter, and responsive, browser and
  accessibility checks.

## Known limitations

- This candidate is experimental. The interpreter remains the semantic
  reference, and the native backend rejects unsupported shapes instead of
  claiming universal native coverage.
- `Measurement<Quantity<D>>` and `Array<Measurement<T>>` remain guarded. The
  `dyn Trait` ownership support boundary is limited to the combinations in the
  ownership matrix; unlisted nested wrappers and cancellation states are not
  implied to work through native HIR/IR.
- Static effect semantics are not a purity guarantee. R3 provenance remains
  incomplete (29 bundles are base-ready; none has complete host/effect evidence,
  and 4,266 effect calls remain unresolved).
- General cross-platform numerical equivalence, upstream GitHub Linguist
  recognition and a public package registry are not included.
- Linux ARM64, Intel macOS, musl builds and package-manager channels are not
  part of this candidate matrix.

## Examples

Start with `examples/hello.ostrin`, `examples/measurement_phi.ostrin`,
`examples/native_dyn_trait_record_field.ostrin` and `examples/viz_table.ostrin`.
The gallery and Scientific Lab contain reproducible examples of plots, tables,
3D scenes and animations.

## Reporting problems

Open an issue at <https://github.com/sircalch/Ostrin/issues/new/choose>. Include
`ostrinc --version`, your operating system and architecture, the smallest
program that reproduces the problem, the command you ran and its full output.
For native compilation problems, include your C compiler and its version.

See [`CHANGELOG.md`](../../CHANGELOG.md) for the detailed v0.2.0 history and
implementation scope, and [`v0.2.0-publication.md`](v0.2.0-publication.md) for
tag and post-publication verification steps.
