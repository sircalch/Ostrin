Ostrin 0.2.0 is an **experimental developer release** of the Ostrin compiler
(`ostrinc`). It builds on the 0.1.0 line with stronger scientific ownership,
numerical validation, reproducibility and visualization workflows. It is meant
for trying the language and reporting problems, not for production use; the 0.x
compatibility policy allows syntax, diagnostics and APIs to change.

## What is included

- Scalar `Measurement<Float>` ownership through records, calls, cloning,
  collections, branches, loops, closures, results and deferred tasks.
- Numerical methods for LU, Cholesky, QR, SVD and symmetric eigenpairs, checked
  against independent residuals and declared per-case tolerances.
- Typed HIR/IR and native C lowering for additional managed values, including
  the tested `dyn Trait` ownership combinations documented in
  [`docs/ownership-matrix.md`](../ownership-matrix.md). The measured compiler
  core contains 7,198 IR and 41 HIR bodies with zero AST fallbacks; this does
  not imply every valid program shape is supported by IR/C.
- Scientific plots, tables, 3D scenes and animation, with a browser gallery,
  playground and reproducible figure bundles.
- R1 replay for registered input-driven experiments, plus source, input,
  dependency, effect and runtime evidence in provenance artifacts. Runtime
  provenance is partial and cross-platform numerical equivalence is not
  claimed.
- A conservative effects inventory that separates known effects from
  unresolved calls; it is not a static purity guarantee.
- Native and WASI execution paths, a community starter project and expanded
  browser, responsive and accessibility checks.

## Known limitations

- `Measurement<Quantity<D>>` and `Array<Measurement<T>>` remain guarded until
  their ownership and native ABI contracts are complete.
- `dyn Trait` support is limited to the combinations with evidence in the
  ownership matrix. Other nested wrappers, aggregate shapes and task
  cancellation states are not implied to work through native HIR/IR.
- Static effect semantics, complete R3 provenance, general cross-platform
  numerical equivalence, upstream GitHub Linguist recognition and a public
  package registry are not included.
- Ostrin remains experimental. The interpreter is the semantic reference;
  the native backend rejects unsupported shapes rather than claiming universal
  native coverage.
