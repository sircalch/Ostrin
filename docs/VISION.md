# Ostrin vision

Ostrin aims to make scientific software harder to get wrong, easier to
reproduce, beautiful to explore, and efficient to execute.

Its distinct foundation is a statically checked language where physical
dimensions participate in types. That foundation should work together with
clear ownership, numerical methods validated by residuals, experiments that
capture their inputs and provenance, and interactive visualizations that
retain their scientific meaning.

The long-term ambition is a credible scientific computing system with a useful
language, compiler, libraries, editor support, reproducible research workflow,
and a polished public experience. Ostrin should earn trust through evidence:
tests, documented limits, performance measurements, installation checks, and
real external projects.

This is a direction, not a claim that Ostrin already matches the ecosystem or
adoption of Python, Julia, or Wolfram. The current implementation is tracked in
[`../ESTADO_Y_PLAN.md`](../ESTADO_Y_PLAN.md); sequenced future work is tracked
in [`../ROADMAP.md`](../ROADMAP.md).
